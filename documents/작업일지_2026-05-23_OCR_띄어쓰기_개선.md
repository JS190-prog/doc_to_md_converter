# 작업일지: OCR 띄어쓰기 개선

## 일자

- 2026-05-23

## 작업 개요

- 스캔 PDF OCR 결과에서 글자 인식은 정확하지만 원본 띄어쓰기와 간격이 충분히 보존되지 않는 문제를 개선
- PaddleOCR 결과의 텍스트 박스 좌표를 활용해 같은 줄 안의 실제 가로 간격을 공백 수로 복원
- 후처리 단계에서 복원된 다중 공백이 다시 1칸으로 축약되지 않도록 보호

## 문제 원인

- 기존 `_join_line_tokens()`는 OCR 박스 사이 간격이 충분히 있으면 항상 공백 1개만 삽입했다.
- 기존 `_post_process_text()`는 `[ \t]{2,}` 패턴으로 연속 공백을 모두 1개로 줄였다.
- 이 때문에 원본 PDF에서 단어 사이, 항목 사이, 컬럼성 간격이 넓어도 Markdown 결과에는 동일하게 반영되지 않았다.

## 상세 작업 내역

1. OCR 박스 간격 기반 공백 복원

- `src/converters/ocr_engine.py`의 `_join_line_tokens()` 수정
- 같은 줄의 OCR 토큰별 박스 너비와 글자 수를 이용해 평균 글자폭을 추정
- 인접 토큰 사이의 `x0 - x1` 간격을 기준으로 공백 수를 계산
- 매우 가까운 박스는 기존처럼 붙여 쓰고, 의미 있는 간격은 1개 이상 최대 12개 공백으로 복원

1. 공백 계산 헬퍼 추가

- `_estimate_line_char_width(tokens)` 추가
  - 토큰 박스 너비 / 글자 수의 중앙값으로 줄 단위 글자폭 추정
- `_spaces_for_gap(gap, char_width, ref_h)` 추가
  - OCR 박스 사이 실제 간격을 명목 공백폭으로 나눠 공백 수 산정

1. 후처리 공백 보존

- `_post_process_text()`에서 연속 공백을 무조건 1칸으로 축약하던 로직 제거
- 탭은 일반 공백으로만 정규화
- 한국어 띄어쓰기 보정(`fix_korean_spacing`) 적용 전에 2칸 이상 공백을 임시 토큰으로 보호
- 보정 후 임시 토큰을 원래 공백 길이로 복원

## 변경 파일

- `src/converters/ocr_engine.py`

## 검증 사항

- `python -m py_compile .\src\converters\ocr_engine.py`
  - 문법 검증 통과
- OCR 엔진 인스턴스 초기화 없이 `_join_line_tokens()`와 `_post_process_text()`를 직접 호출하는 소규모 테스트 수행
  - 좌표 간격이 넓은 토큰 사이에 다중 공백이 생성되는 것 확인
  - 후처리 이후에도 다중 공백이 유지되는 것 확인

## 남은 한계

- PaddleOCR이 한 줄 전체를 하나의 박스로 반환하고 내부 공백을 누락하는 경우에는 좌표 기반으로 원본 공백을 완전히 복원할 수 없다.
- 이 경우는 기존 한국어 띄어쓰기 보정 규칙으로 보완되지만, 원본과 100% 동일한 간격 복원은 OCR 박스가 토큰 단위로 분리되어 있을 때 가장 잘 동작한다.
